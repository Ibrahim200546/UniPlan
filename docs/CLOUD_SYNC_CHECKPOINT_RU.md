# Состояние облачной интеграции

Облачное сохранение учебных записей в этом контрольном состоянии **не реализовано и не проверено**. Room остаётся источником локальных данных. Авторизация через Supabase сама по себе не отправляет предметы, задания, занятия и заметки на сервер.

`SUPABASE_SCHEMA_DRAFT.sql` содержит проект таблицы, правил RLS и функции сравнения версий. Скрипт не выполнялся. Соединение Supabase MCP возвращало `Unknown tool`; запуск локального CLI завершился сетевой ошибкой `ENOTFOUND registry.npmjs.org`. Файл намеренно не назван применённой миграцией.

Для завершения нужны: подтверждённая серверная схема, JSON-кодек со строгой проверкой и безопасным переназначением локальных ID, Room-метаданные версии/изменений, последовательный координатор синхронизации, обработка конфликтов с явным выбором пользователя и проверки двух аккаунтов/двух устройств. Нельзя включать автоматическую перезапись данных только на основании успешного входа.

Предлагаемый сетевой контракт: GET `/rest/v1/uniplan_state?select=revision,payload` возвращает собственную строку по RLS. POST `/rest/v1/rpc/save_uniplan_state` принимает `expected_revision` и `data`; `ok=true` подтверждает новую версию, `conflict=true` требует выбора. Идентификатор владельца берётся из `auth.uid()`, а не из payload. В payload не должны находиться пароль, refresh token, access token или ключ сервиса.

Текущая рабочая версия сохраняет прежнюю demo/Firebase-авторизацию. SupabaseHttp и SecureSessionStore — подготовительные классы, пока не подключённые к входу. Удаление demo, вход/регистрация, создание аккаунта ibrahim и перенос данных в Supabase ещё не выполнены. Пароль пользователя не хранится в исходниках.
