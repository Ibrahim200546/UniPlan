# UniPlan — Supabase

Основной вариант сборки: **supabaseDebug**. Настоящий вход и регистрация по email/паролю, локальная Room-база и сохранение профиля, предметов, заданий, расписания и текстов заметок в Supabase.

Проект: https://supabase.com/dashboard/project/rrhuqwaytpeerirbnhlc

Откройте эту папку в Android Studio. Gradle JDK: 21. Выберите Build Variant **supabaseDebug**, затем Run app. SDK 35 и Build Tools 35.0.0. Публичный publishable key включён в клиент; приватных серверных ключей нет. Можно переопределить supabase.url и supabase.key в local.properties.

Сохранение в Room происходит сразу. Облачная синхронизация выполняется при входе и после изменений; повторный запуск — Профиль → Синхронизировать. При конфликте двух устройств приложение предлагает выбрать локальную или облачную версию. При отсутствии сети записи остаются на устройстве. Файлы TXT из внешнего хранилища не загружаются; текст заметок синхронизируется.

Новый аккаунт начинает с пустого плана. На главной нажмите «Добавить предмет», затем создайте занятие или задание. Личные демоданные не переносятся в новые аккаунты.

Если Confirm email включён, пользователь должен подтвердить письмо перед входом. Для отправки писем внешним пользователям требуется SMTP в Supabase. Приложение не обходит подтверждение email.

Миграции находятся в supabase/migrations. RLS ограничивает данные владельцем auth.uid(). RPC сохраняет снимок только при совпадении revision, поэтому устаревшее устройство не затирает данные незаметно.

Проверено на сервере: вход, обновление токена, запись и чтение через REST, создание/обновление снимка, отклонение устаревшей версии, изоляция второго аккаунта и запрет записи с чужим user_id. Тестовые SQL-данные откатили транзакцией. Security Advisors: без замечаний после ограничения доступа к внутреннему event-trigger.
